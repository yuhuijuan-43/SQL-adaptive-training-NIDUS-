# SQL 填空题格式规范

## 概述

题库中每道题是一个 **填空题**（Fill-in-the-blank），用户直接在输入框中手写 SQL，不提供选择题选项。所有题目以 JSON 数组形式存储在 `questions.py` 中。

---

## 字段定义

### 1. `source`（字符串）
题目来源标识。

| 值 | 说明 |
|----|------|
| `"curated"` | 手工编写的原创题目 |
| `"sqlzoo"` | 爬取自 SQLZoo |
| `"pgexercises"` | 爬取自 PostgreSQL Exercises |
| `"curated_web"` | 补充编写的网络风格题目 |

### 2. `category`（字符串）
知识点分类，与知识图谱节点一对一映射。

| 分类 | 知识点 | 说明 |
|------|--------|------|
| `select_basic` | SELECT 基础查询 | 查询指定列、全部列 |
| `where_basic` | WHERE 条件筛选 | 单条件过滤 |
| `where_andor` | AND / OR 多条件 | 组合多个条件 |
| `where_like` | LIKE 模糊查询 | `%` `_` 通配符 |
| `where_null` | IS NULL | 空值判断 |
| `where_in` | IN 运算符 | 值列表匹配 |
| `where_between` | BETWEEN | 范围查询 |
| `order_by` | ORDER BY | 排序（ASC/DESC） |
| `limit_offset` | LIMIT / OFFSET | 分页 |
| `aggregate_basic` | 聚合函数 | COUNT/SUM/MAX/MIN |
| `group_by` | GROUP BY | 分组聚合 |
| `having` | HAVING | 分组后过滤 |
| `avg` | AVG | 平均值 |
| `count_distinct` | COUNT(DISTINCT) | 去重计数 |
| `alias` | AS 别名 | 列/表别名 |
| `distinct` | DISTINCT | 去重 |
| `case_when` | CASE WHEN | 条件分支 |
| `join_inner` | INNER JOIN | 内连接 |
| `join_left` | LEFT JOIN | 左连接 |
| `join_self` | 自连接 | 同一表连接自身 |
| `join_multi` | 多表 JOIN | 连续 JOIN 多表 |
| `join_full` | FULL JOIN | 全外连接 |
| `subquery_basic` | 子查询基础 | WHERE 中子查询 |
| `subquery_exists` | EXISTS | 存在性检查 |
| `subquery_all` | ALL / ANY | 多行比较 |
| `subquery_select` | SELECT 中子查询 | 标量子查询 |
| `cte` | CTE (WITH) | 公共表表达式 |
| `window` | 窗口函数 | ROW_NUMBER/RANK/LAG |
| `dml` | DML | INSERT/UPDATE/DELETE |
| `string` | 字符串函数 | CONCAT/LIKE/REPLACE |
| `date` | 日期函数 | 日期比较/计算 |
| `union` | UNION | 合并查询结果 |

### 3. `difficulty`（字符串）

| 值 | 说明 |
|----|------|
| `"easy"` | 单表、基础 SELECT/WHERE |
| `"medium"` | JOIN、聚合、子查询 |
| `"hard"` | 窗口函数、CTE、FULL JOIN、递归 |

### 4. `title`（字符串）
题目标题。不超过 80 字符。

```
"查询所有员工"
```

### 5. `description`（字符串）
题干描述。可含换行 `\n`。

```
"查询 employees 表中所有员工的全部信息。"
```

多表时：
```
"查询每位员工的姓名及其所属部门名称。\n\n表结构：\nemployees(id, name, dept_id)\ndepartments(id, dept_name)"
```

### 6. `table_schema`（字符串）
建表语句。多表用 `\n` 分隔。

单表：
```
"CREATE TABLE employees (id INT, name VARCHAR(50), department VARCHAR(50), salary DECIMAL(10,2), age INT);"
```

多表：
```
"CREATE TABLE orders (id INT, customer_id INT, product_id INT, quantity INT, order_date DATE);\nCREATE TABLE customers (id INT, name VARCHAR(50), city VARCHAR(50));"
```

数据类型自动映射到 SQLite：

| 原类型 | SQLite |
|--------|--------|
| `INT` / `BIGINT` / `SMALLINT` | `INTEGER` |
| `VARCHAR(n)` / `CHAR(n)` / `TEXT` | `TEXT` |
| `DECIMAL(p,s)` / `FLOAT` / `DOUBLE` | `REAL` |
| `DATE` / `DATETIME` / `TIMESTAMP` | `TEXT` |
| `BOOLEAN` | `INTEGER` |

### 7. `initial_data`（字符串）
INSERT 初始化数据。多表用 `\n` 分隔，按外键依赖顺序书写。

```
"INSERT INTO customers VALUES (1, '张三', '北京'), (2, '李四', '上海');\nINSERT INTO orders VALUES (1, 1, 500, '2024-01-01');"
```

**约束：**
- 字符串值使用**单引号**
- NULL 使用 `NULL`（无引号）
- 日期使用 `'YYYY-MM-DD'`

### 8. `correct_answer`（字符串）
标准答案 SQL。以分号结尾，可执行。

```
"SELECT * FROM employees WHERE department = '技术部' AND salary > 10000;"
```

### 9. `explanation`（字符串）
答案解析，解释 SQL 执行逻辑与语法要点。

```
"AND 表示两个条件同时满足，筛选出技术部中工资大于 10000 的员工。"
```

### 10. `expected_output`（字符串）
执行 `correct_answer` 后的预期结果，ASCII 表格格式。

```
"id | name | department | salary  | age\n---+------+------------+---------+----\n1  | 张三   | 技术部        | 12000.0 | 28 \n3  | 王五   | 技术部        | 15000.0 | 32 "
```

**格式规则：**
- 第 1 行：列标题，` | ` 分隔
- 第 2 行：分隔线，`-+-` 分隔
- 第 3+ 行：数据行，` | ` 分隔
- NULL 值显示为 `NULL`

## 题目 JSON 示例

### 单表基础题
```json
{
    "source": "curated",
    "category": "select_basic",
    "difficulty": "easy",
    "title": "查询所有员工",
    "description": "查询 employees 表中所有员工的全部信息。",
    "table_schema": "CREATE TABLE employees (id INT, name VARCHAR(50), department VARCHAR(50), salary DECIMAL(10,2), age INT);",
    "initial_data": "INSERT INTO employees VALUES (1, '张三', '技术部', 12000, 28), (2, '李四', '市场部', 9000, 35), (3, '王五', '技术部', 15000, 32);",
    "correct_answer": "SELECT * FROM employees;",
    "explanation": "使用 SELECT * 查询表中所有列和所有行。",
    "expected_output": "id | name | department | salary  | age\n---+------+------------+---------+----\n1  | 张三   | 技术部        | 12000.0 | 28 \n2  | 李四   | 市场部        | 9000.0  | 35 \n3  | 王五   | 技术部        | 15000.0 | 32 "
}
```

### 多表 JOIN 题
```json
{
    "source": "curated",
    "category": "join_multi",
    "difficulty": "medium",
    "title": "多表连接查询",
    "description": "查询所有订单的订单号、客户姓名和商品名称。",
    "table_schema": "CREATE TABLE orders (id INT, customer_id INT, product_id INT, quantity INT, order_date DATE);\nCREATE TABLE customers (id INT, name VARCHAR(50), city VARCHAR(50));\nCREATE TABLE products (id INT, name VARCHAR(50), category VARCHAR(50), price DECIMAL(10,2), stock INT);",
    "initial_data": "INSERT INTO customers VALUES (1, '张三', '北京'), (2, '李四', '上海');\nINSERT INTO products VALUES (1, '键盘', '电子产品', 150, 100), (2, '鼠标', '电子产品', 30, 200);\nINSERT INTO orders VALUES (1, 1, 1, 2, '2024-01-01'), (2, 2, 2, 1, '2024-01-02');",
    "correct_answer": "SELECT o.id, c.name, p.name FROM orders o JOIN customers c ON o.customer_id = c.id JOIN products p ON o.product_id = p.id;",
    "explanation": "通过 JOIN 将 orders 与 customers、products 关联，获取订单、客户和商品信息。",
    "expected_output": "id | name | name\n---+------+-----\n1  | 张三   | 键盘  \n2  | 李四   | 鼠标  "
}
```

## 弃用字段

填空题不需要以下字段（但兼容保留，旧数据中含有的可忽略）：

| 字段 | 说明 | 状态 |
|------|------|------|
| `options` | 选择题选项（`|` 分隔） | **弃用**，新增题目不再填写 |
| `option_explanations` | 选项解析（`|` 分隔） | **弃用**，新增题目不再填写 |

系统中现有题目仍包含这两个字段（历史遗留），但前端刷题页面在**填空题模式下不展示选项**。

## 前端渲染顺序

填空题的页面渲染顺序固定如下：

```
┌─ 分类 · 难度标签 ────────────────────────┐
│  join_multi  · 中等  · 填空题               │
├─ 标题 ────────────────────────────────────┤
│  多表连接查询                              │
├─ 题干描述 ───────────────────────────────┤
│  查询所有订单的订单号、客户姓名和商品名称。    │
├─ 建表 SQL + 测试数据（可折叠） ────────────┤
│  [展开 SQL]                                │
├─ 预期输出表格 ────────────────────────────┤
│  id │ name │ name                         │
│  ───┼──────┼─────                         │
│  1  │ 张三   │ 键盘                          │
│  2  │ 李四   │ 鼠标                          │
├─ 用户输入区域 ────────────────────────────┤
│  ┌──────────────────────────────────────┐ │
│  │ 手动输入你的 SQL 语句...               │ │
│  └──────────────────────────────────────┘ │
├─ 提交按钮 ───────────────────────────────┤
│  [提交答案]                               │
└───────────────────────────────────────────┘
```

**组件层级说明：**

| 层级 | 组件 | 说明 |
|------|------|------|
| 1 | 标签栏 | `category` + `difficulty` + "填空题" |
| 2 | 标题 | `title` |
| 3 | 描述 | `description`，左竖线高亮区块 |
| 4 | SQL 面板 | 可折叠，显示 `table_schema` + `initial_data` |
| 5 | 预期输出 | `expected_output` 渲染为 HTML 表格 |
| 6 | 输入框 | `<textarea>`，等宽字体，语法输入 |
| 7 | 提交按钮 | 异步提交，答案比对 + 反馈 |

## 答案比对逻辑

系统使用标准化 SQL 对比进行评分，步骤如下：

```
用户输入 ─→ 去除首尾空格、分号 ─→ 小写化 ─→ 合并空白
                                               ↓
正确答案 ─→ 去除首尾空格、分号 ─→ 小写化 ─→ 合并空白
                                               ↓
                                         相等判断 → 正确/错误
```

特殊处理（`backend/app.py` 中 `normalize_sql` 函数）：
- 移除引号（消除单引号/双引号差异）
- SELECT 列按字母排序后比较（消除列顺序差异）
- 去除 AS 关键字后排序（消除别名差异）

## 新增题目流程

### 步骤 1：编写 JSON
按本规范在 `questions.py` 的数组中追加对象。**不填写 `options` 和 `option_explanations` 字段。**

### 步骤 2：生成预期输出
```bash
python backend/generate_expected_output.py
```

### 步骤 3：重新播种数据库
```bash
python -c "import sys; sys.path.insert(0, 'backend'); from database import init_db, seed_questions, seed_knowledge_graph; init_db(); seed_questions(); seed_knowledge_graph()"
```

### 步骤 4：重启服务
```bash
python backend/run.py
```

## 多表命名约定

| 项目 | 约定 | 示例 |
|------|------|------|
| 表名 | 英文复数 | `employees`, `orders` |
| 主键 | `id INT` | 每表第一列 |
| 外键 | `引用表名_id INT` | `customer_id`, `dept_id` |
| 字符串列 | `VARCHAR(50)` | 名称、城市等 |
| 数值列 | `DECIMAL(10,2)` | 金额、工资等 |
| 日期列 | `DATE` | 订单日期等 |

INSERT 按外键依赖顺序书写（先插入被引用的表）。
