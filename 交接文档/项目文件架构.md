# 项目文件架构

基于知识图谱点亮机制与自适应出题算法的 SQL 练习平台。本文档描述项目文件结构、各文件功能与分类缘由（2026-09 更新版）。

## 一、结构总览

```
SQL自适应训练/
├── backend/            # Flask 后端（运行时代码）
├── frontend/           # 前端页面（原生 HTML/CSS/JS，无框架）
├── data/               # 题库数据源（JSON / CSV，可被 seeding 重建）
├── docs/               # 设计文档、规范与内部手册
├── tools/              # 一次性工具脚本
├── 网络爬虫/           # 牛客/LeetCode 题库爬虫子项目（独立 npm 依赖）
├── ngrok/              # 内网穿透二进制（本地工具，不入库）
├── start_server.bat    # Windows 一键启动脚本
├── README.md           # 项目说明（对外门面）
├── 项目文件架构.md     # 本文档
├── .gitignore          # 版本控制忽略规则
├── .mcp.json           # Claude Code MCP 配置（含密钥，不入库）
└── .claude/            # Claude Code 本地配置
```

## 二、backend/ — Flask 后端

### 分层结构（基础设施 → 数据访问 → 业务逻辑 → 入口）

| 文件 | 功能 |
|---|---|
| `app.py` | **主入口**：全部路由 / API / 鉴权 / 前端页面托管（`FRONTEND_DIR` 指向项目根/frontend） |
| `run.py` | 服务启动器：初始化 DB → 启动治理 → 备份 → 灌题库 → 启动服务（waitress 生产级） |
| `db.py` | SQLite 连接管理与建表；`DB_PATH` = backend/questions.db |
| `backup.py` | SQLite 自动备份（2026-09-03）：启动 / 题库重建等风险动作前在线备份到 `backups/`，保留最近 20 份（`DB_BACKUP_KEEP` 可调） |
| `maintenance.py` | 运行时数据治理（2026-09-06）：user_progress 保险丝（超 10 万行动态压缩重复答对行）、admin_sessions 过期 token 清理；全部静默失败 |
| `repositories.py` | 数据访问层：题目 / 用户 / 进度查询，把 SQL 从路由中抽出 |
| `auth.py` | 注册 / 登录 / 会话管理 / 限流 |
| `oauth.py` | GitHub OAuth2 授权码登录（凭证读 `oauth_config.json`，已被 gitignore） |
| `logs.py` | 活动动态与系统日志（2026-09-03）：activity_log（封顶 1.2 万条）/ system_logs（封顶 5 千条），写入静默失败 |
| `engine.py` | **自适应出题引擎** + 知识图谱点亮规则（规则3 只计不同题目，同题重复答对不叠加） |
| `sql_judge.py` | **SQL 判题引擎**：规范化 / 只读校验 / 沙箱执行 / 结果比对 |
| `seeding.py` | 题库种子重建：从 `data/questions.json`（483 题）与 `data/exam_questions.json`（42 题）加载，库内条数不符时自动重建（重建会清理对不上 id 的 practice 答题记录） |
| `scraper.py` | w3resource 题库抓取（早期建库工具） |
| `migrate_official_tags.py` | 一次性迁移官方知识标签脚本 |
| `requirements.txt` / `requirements-dev.txt` | 运行 / 开发依赖清单 |
| `oauth_config.json` / `.example.json` | OAuth 密钥（真实文件仅本地）/ 模板（入库） |
| `questions.db` | 运行时数据库（gitignore；`backups/` 自动备份同样不入库） |
| `tests/` | pytest 套件（178 用例）：`test_api_security`、`test_backup_and_schema`、`test_ewma_mastery`、`test_journey_flow`、`test_journey_lights`、`test_oauth`、`test_seed_rebuild`、`test_sql_judge` + `conftest.py` 夹具 |

## 八、分类缘由

1. **生命周期分层**：运行时经常改的（backend / frontend）独立成目录；低频一次性工具（tools、scraper、migrate）不污染主流程。
2. **可重建与不可重建分离**：`questions.db`、`backups/`、`node_modules`、`_full` 备份等可重建内容不入版本库；`data/questions.json` 等当前源由 `seeding.py` 重建 DB。
3. **敏感信息隔离**：`oauth_config.json`（client_secret）、`.mcp.json`（API 密钥）gitignore，只留模板入库。
4. **公开与内部文档分流**：内部手册、审计、日志通过 .gitignore 留在本地，仓库只保留对外可见的 README + 规范。
5. **数据与代码分离**：题库 JSON 放 `data/` 根级目录，不绑定 backend 包结构，被 seeding / tools 独立读取。

## 九、关键依赖约束（改动前必读）

| 依赖 | 说明 |
|---|---|
| `seeding.py` ↔ `data/questions.json`、`data/exam_questions.json` | 路径基于 `__file__` 相对定位，移动数据文件必须同步改 `seeding.py:421,422,467` 与 `tests/test_seed_rebuild.py:14,20`；重建按「库内题数 vs 文件题数」比对触发，**不要手工直接增删 questions.json**，扩题走 `tools/import_questions.py` |
| `maintenance.py` ↔ `repositories.save_answer` | 保险丝挂钩在答题入库后；阈值 env：`USER_PROGRESS_MAX_ROWS`（默认 100000）、`USER_PROGRESS_CHECK_EVERY`（默认 500，0 关闭）；压缩不删答错行/每题首条答对行/组内最近 30 条 |
| `engine.py` 规则3 ↔ `user_progress` | 点亮计数为 `COUNT(DISTINCT question_id)`（2026-09-06 起），同题循环复用产生的重复答对行不影响点亮 |
| `app.py` ↔ `frontend/` | `FRONTEND_DIR`（app.py:117）锚定项目根/frontend，frontend 目录整体不可移动 |
| 前端页面 ↔ 页面间 | 全部**相对路径**互链，同目录内移动安全；后端无扩展名路由（`/login`、`/knowledge-map` 等）不受文件移动影响 |
| `start_server.bat` ↔ `backend/` | bat 用 `%~dp0` 锚定自身目录，与 backend/ 相对位置不可变 |
| `oauth.py` ↔ `backend/oauth_config.json` | 基于 `__file__`，随 backend 内部移动安全 |
